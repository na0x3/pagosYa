# Starters (Plan 1 of 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** New stores start from one of several finished starter stores (harvested from the owner's approved stores) instead of always plain Esencial, YAPI picks the closest one, and the merchant can switch with «Probar otro estilo».

**Architecture:** A starter is a template folder in `packages/store-templates/templates/<id>/` with its own source files and a `starter` block in `template.json`. Esencial-based starters (`extends: "esencial"` + `preset` + own `components/`) reuse the whole master path (fill, refill, menus, fashion) with their own source; own-structure starters reuse the Plantillas copy-slot path. A harvest script copies an approved store's latest revision into a starter folder and refuses to finish while brand words or store-only assets remain. The chat's first build picks a starter with a pure, tested function and applies it through the existing `applyMaster` / `applyPlantillaFilled`.

**Tech Stack:** Node (CommonJS registry in `packages/store-templates`, `node --test`), NestJS + Prisma (`apps/api`, jest), TypeScript Studio (`apps/merchant-studio`, vitest), ChatGPT-plan bridge for live runs.

**Spec:** `docs/superpowers/specs/2026-10-24-starters-and-parts-design.md` (sections 1, 2, Rollout, Testing). Plans 2 (parts shelf) and 3 (gap starters + live check) follow.

## Global Constraints

- Never build a new store from scratch; scratch routes (`MASTER_SCRATCH` / `OWN_STRUCTURE` in `source-chat.service.ts`) stay exactly as today and are not extended.
- Flag `YAPI_STARTERS` (default **off** until Task 9's live check): off = today's behaviour byte for byte.
- Existing stores are never changed; only new builds and «Probar otro estilo» on a first build use starters.
- Harvesting reads the dev DB read-only (Prisma `findFirst`/`findMany` only). Never `prisma migrate|db push|reset|diff` (memory: dev DB wiped 2026-09-25).
- No third-party or brand photos in a starter: demo photos only from `packages/store-templates/templates/esencial/demo/` or other existing template demo folders.
- No Amboras code copied.
- Saving any file under `apps/api` restarts `nest --watch` and kills running YAPI jobs: check `SELECT count(*) FROM "StoreSourceChatJob" WHERE status IN ('QUEUED','RUNNING')` is 0 first. Type-check with `npx tsc --noEmit --incremental false -p apps/api`.
- Live runs: stack started with `pnpm dev:chatgpt` only; one YAPI run at a time.
- Owner gate after Task 3: the PEPPA starter's look is approved by the owner before Tasks 4+ wire it into real builds.
- Studio changes need `pnpm --filter @pagosya/merchant-dashboard run build:studio` before live checks.

## Review Focus

1. A harvested component still carries brand words inside CSS `content:` strings, `alt`/`aria-label` attributes or comments — the harvest scan must read the whole file text, not only JSX text (Task 2 test «finds brand words in CSS content and alt text»).
2. A harvested component references a store-only asset (`assets/image-<hash>.jpg`, `/v1/uploads/…`) that will not exist in a new store — harvest must fail on it (Task 2 test «flags store-only asset paths»).
3. A fashion catalogue picked a non-fashion starter (fashion card/page then missing) — `pickStarter` must force a fashion-capable starter (Task 7 test «a fashion store always gets a fashion starter»).
4. «Probar otro estilo» after the merchant asked for their own change would throw away their edit — the endpoint must refuse once any revision came from a merchant request (Task 8 test «refuses after a merchant edit»).
5. A starter whose `fits` overlap another's makes picking unstable between runs — `pickStarter` must be deterministic for the same input (Task 7 test «same words, same starter»).

// packages/store-templates/tools/harvest-core.mjs
/** Spec 2026-10-24 §1 Harvesting: keep a store's authored source, swap known brand text, and list everything that still
 *  names the store or points at its own uploads. Pure: the script does the IO. */
const KEEP = path => (path.startsWith('components/') && path.endsWith('.tsx')) || path === 'styles/globals.css';
const ASSET = /(?:\bassets\/(?!fonts\/)[\w./-]+|\/v1\/uploads\/[\w.-]+)/g;
const escapeRe = text => text.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');

export function harvestFiles({ files, brand, replacements }) {
  const words = [...new Set(brand.map(word => word.trim()).filter(word => word.length >= 3))];
  const brandRe = words.length ? new RegExp(words.map(escapeRe).join('|'), 'gi') : null;
  const kept = files.filter(file => KEEP(file.path)).map(file => ({ path: file.path, content: Object.entries(replacements).reduce((text, [from, to]) => text.split(from).join(to), file.content) }));
  const findings = [];
  for (const file of kept) file.content.split('\n').forEach((line, index) => {
    for (const match of brandRe ? line.matchAll(brandRe) : []) findings.push({ path: file.path, line: index + 1, kind: 'brand', text: match[0] });
    for (const match of line.matchAll(ASSET)) findings.push({ path: file.path, line: index + 1, kind: 'asset', text: match[0] });
  });
  return { files: kept.sort((a, b) => a.path.localeCompare(b.path)), findings };
}
```

/** Spec 2026-10-24 §2: the starter closest to the business, chosen in code before the fill so the right fill path runs. */
export type StarterChoice = { id: string; fits: readonly string[]; fashion?: boolean; order: number };
const plain = (text: string) => text.normalize('NFD').replace(/\p{M}/gu, '').toLowerCase();
const has = (text: string, word: string) => new RegExp(`(?<!\\p{L})${plain(word).replace(/[.*+?^${}()|[\]\\]/g, '\\$&')}(?!\\p{L})`, 'u').test(text);
const CALM = /(?<!\p{L})(minimalista|minimal|lujo|elegante)(?!\p{L})/u;
const PLAYFUL = /(?<!\p{L})(divertid\p{L}*|alegre|colorid\p{L}*|juguet\p{L}*)(?!\p{L})/u;

export function rankStarters(input: { text: string; fashion: boolean; starters: readonly StarterChoice[]; recent: readonly string[] }): string[] {
  const text = plain(input.text);
  const fashionOnes = input.starters.filter(s => s.fashion);
  const eligible = input.fashion && fashionOnes.length ? fashionOnes : [...input.starters];
  const base = new Map(eligible.map(s => {
    let score = s.fits.filter(word => has(text, word)).length;
    if (CALM.test(text) && s.fits.some(w => w === 'minimal' || w === 'lujo')) score += 2;
    if (PLAYFUL.test(text) && s.fits.includes('alegre')) score += 2;
    return [s.id, score] as const;
  }));
  const positives = eligible.filter(s => base.get(s.id)! > 0);
  const score = (s: StarterChoice) => base.get(s.id)! - (input.recent.includes(s.id) && positives.length > 1 ? 3 : 0);
  if (!positives.length) return [...eligible].sort((a, b) => (a.id === 'esencial' ? -1 : b.id === 'esencial' ? 1 : a.order - b.order || a.id.localeCompare(b.id))).map(s => s.id);
  return [...eligible].sort((a, b) => score(b) - score(a) || a.order - b.order || a.id.localeCompare(b.id)).map(s => s.id);
}

export const pickStarter = (input: Parameters<typeof rankStarters>[0]) => rankStarters(input)[0] ?? 'esencial';
```
