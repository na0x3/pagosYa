# Cobros (D1) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A merchant creates a cobro on the phone or the web in under a minute, shares it by WhatsApp, email or a copied link, the customer opens a branded page and pays it through the existing checkout, and the cobro moves sent → viewed → paid / overdue with reminders.

**Architecture:** D0's `BusinessDocument` gains a payment link (`paymentIntentId`, `paidAt`) and an `autoReminders` flag. A new `CobrosService` creates or reuses a PaymentIntent for the frozen total, sends reminders and runs the overdue/reminder maintenance from a worker. The payment success transaction marks the cobro paid through a small helper. The checkout app renders `/d/:token`; the merchant dashboard gets a "Documentos → Cobros" view built as its own modules.

**Tech Stack:** NestJS + Prisma (jest, ts-jest `rootDir: src`), checkout Vite + vitest/jsdom, merchant dashboard vanilla ES modules (`node --test`, Playwright).

**Spec:** `docs/superpowers/specs/2026-09-25-cobros-design.md` (§2 decisions 1–14).

## Global Constraints

- Only these paths are edited; `packages/storefront-kit/**`, `apps/api/src/storefront-source/**`, `apps/api/src/stores/store-dna.ts`, `apps/checkout/src/checkout/payment-result.ts` and `apps/checkout/src/source-*` belong to another agent. `apps/checkout/src/main.ts` gets one import and one route block, re-read right before editing.
- Nothing inside a payment's success transaction may throw or hit a unique violation (a Postgres error aborts the transaction and rolls back a captured payment): the hook uses conditional `updateMany` and `createMany({ skipDuplicates: true })`.
- Every status write is conditional (`updateMany where status in …`), as in D0.
- Money is integer minor units; all copy is Spanish.
- Jest paths are relative to `apps/api/src`: `cd apps/api && npx jest business-documents`.
- Commit only this plan's paths: `git commit -m "…" -- <paths>`.

## Review Focus

1. A second success callback, or a success for a voided cobro, must not abort the payment transaction → Task 3 test (`skipDuplicates`, `payment_after_close`).
2. Pay must never charge the working copy: the amount comes from the latest *sent* version, and an edit + re-send produces a new intent → Task 4 test.
3. Two concurrent Pagar clicks must reuse one intent (row lock) → Task 4 (`FOR UPDATE` asserted in the fake).
4. The merchant's own preview must not record `viewed` → Task 2 test.
5. Automatic reminders fire once per version even with two API instances, stay inside their windows, and respect the per-store email cap → Task 5 test.
6. The dashboard must never interpolate merchant or customer text unescaped → every render goes through `escapeHtml`; the Playwright spec types `<img onerror>` as a customer name.
