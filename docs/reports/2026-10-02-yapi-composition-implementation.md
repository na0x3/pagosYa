# Product-led YAPI composition

The merchant clarified that there is no personal “no-grid” preference. Design follows the actual products, brand theme, assets and buying task. Catalog grids, category navigation, comparisons and intentional lookbooks are valid. Cards remain coherent within a store; different stores can use different structures across catalog, product detail, cart and checkout review.

Reference observations from public pages: [Hiut](https://hiutdenim.co.uk/) connects product collections with craft, provenance and fit guidance; [Tentree](https://www.tentree.com/) combines category discovery, collections and its evidenced impact story; [Away](https://www.awaytravel.com/) organizes shopping around travel products. These inform composition choices, not copied assets, copy, claims or proven conversion rates. Zara's root page exposed only its market selector to the text browser, so no detailed implementation claim is made about its current storefront. Competitor research and original diagnosis remain in `2026-10-02-yapi-design-coherence-plan.md`; its code observations describe the pre-change state.

## Implemented

- New planner concepts require a bounded page/section composition plan: purpose, geometry, real media roles, mobile behavior and purchase action. Legacy saved designs remain readable. Custom pages must match planned section structure; leftover uploads do not justify a gallery.
- Existing composition families are selected for the merchandise and intent, not just the number of uploaded photos.
- Eight executable commerce recipes expose actual runtime settings to the planner. Product-page hierarchy, cart layout, checkout order-review layout and catalog behavior can vary together. Existing runtime purchase behavior remains authoritative. Recipes require actual variants or alternate photos where their controls need them.
- Structural fingerprints ignore brand copy and cosmetic changes. A bounded database query returns only hashes to the selection logic; an available fresh proposal replaces a repeated structure unless selection was explicit. No paid replanning loop is added. This detects exact structural repetition, not every perceptually similar design.
- Browser checks cover authored pages, including independent galleries and raster background panels. They reject unjustified equal-weight image walls and repeated photo-only sections; they allow purposeful grids and comparisons. No universal photo quota remains.
- Whole-design agent runs reuse desktop/mobile captures for independent model review, including normal catalog, product and checkout views. Technical failures do not trigger paid review. Results cache by workspace version and snapshot digest. At most two reviewer calls permit one local repair; a remaining major issue stops partial. Local edits retain their existing scope.
- Preview commerce DNA and visual direction use the committed design before review, with the pending product theme applied as at save. Final prepared authored pages also receive deterministic checks.
- Visual review shares the request budget and records usage under the `visual` attempt phase. Repeated composition IDs stop despite wording changes. No provider key or another merchant's content is put in the planning prompt.

## Validation and limits

Targeted Jest suites cover composition contracts, product-to-runtime recipes, structural selection, real-browser gallery regressions, provider response boundaries, usage accounting, capture coverage, cache invalidation, repeated defects and review wiring. The focused planning/media/commerce run passed 128 tests; the generation-agent, media and manual-review run passed 43 tests; the generation-service/composition/protocol run passed 101 tests (these groups overlap). Reviewer boundary/selection checks also passed, including incomplete responses and refused remote-image URLs. API TypeScript compilation and whitespace checks passed. Tests use mocked model responses; no paid storefront generation was performed for this change.

The automatic visual gate is connected to whole-design agent runs. The legacy single-call/static and DeepSeek generation paths do not gain that model-review gate in this change. Screenshots assess visible static states, not conversion rates, all cart-drawer states, interactions or unseen details on very long pages. Existing functional checks remain separate. Checkout layout variations concern the storefront order-review presentation; external payment-provider UI is not redesigned. Actual first-attempt quality and conversion improvements still require representative live generations and shopper funnel measurements; neither is claimed as measured here.
