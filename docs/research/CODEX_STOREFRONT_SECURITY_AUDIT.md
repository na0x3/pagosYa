**The strongest protection is the opaque-origin sandbox around hosted storefronts. The largest gaps are an external-navigation escape from its network restrictions and overly broad authorization of LLM-generated catalog changes.**

I verified **2 High and 5 Medium findings; no Critical finding**. This was a read-only code audit of the current checkout on `cleanup/retire-legacy-dashboard`. No files were modified. In-memory checks exercised the actual validators; no live payments, external requests, or browser exploitation were performed. Deployment-specific proxy/CDN protections were not verified.

The lifecycle is: merchant-authenticated chat → model-generated HTML/JS or React components → validation/compilation → immutable source revision → explicit publication pointer → public snapshot API → trusted checkout shell rendering an opaque `srcdoc` iframe. Sensitive operations cross a constrained `postMessage` bridge. Exported standalone stores follow a different, less isolated path.
