**(b) Top 15 gaps, ranked by merchant/shopper impact**

Sizes: **S** localized change; **M** coordinated feature change; **L** pipeline/architecture change.

1. **Hosted storefront mounting waits for the entire catalog’s images — L.**  
   The host awaits image preparation before inserting the iframe. Preparation fetches product galleries, variant photos, and extras with four workers, then converts them to data URLs. Consequently, `loading="lazy"` inside the storefront cannot defer these downloads. **Fix:** render immediately and load appropriately sized images on demand through a constrained asset-serving path. [Mount sequence](/Users/saramia/pagosYa/apps/checkout/src/source-storefront.ts:33), [image queue](/Users/saramia/pagosYa/packages/storefront-preview/src/source-preview-media.ts:60).

2. **Hosted carts lose unsaved changes on refresh and do not persist across sessions — M.**  
   The parent restores from `sessionStorage` and saves only on source-page navigation. Cart mutations attempt `localStorage` inside the opaque sandbox and swallow storage errors; no mutation-to-parent persistence message exists in that path. Adding items and refreshing before navigating therefore restores older state. **Fix:** send validated cart-change events to the parent and persist per store on every change. [Parent storage](/Users/saramia/pagosYa/apps/checkout/src/source-storefront.ts:40), [cart writes](/Users/saramia/pagosYa/packages/storefront-kit/kit/commerce.js:1382), [sandbox storage behavior](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy).

3. **Published source assets travel inside an uncacheable snapshot — L.**  
   The source-site endpoint returns the selected revision’s browser files under `private, no-store`; preview rendering embeds assets as data URLs. This prevents independent HTTP caching of those bundled files, although separately fetched uploads have immutable caching. **Fix:** separate visitor assignment/live data from content-addressed revision assets, served with immutable caching and validators. [Endpoint](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-publishing.controller.ts:56), [snapshot response](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-publishing.service.ts:146), [embedding](/Users/saramia/pagosYa/packages/storefront-preview/src/source-preview.ts:27).

4. **No generated responsive-image pipeline — L.**  
   Uploads store the original bytes; WebP uploads are accepted, but AVIF is absent from the upload allowlist. Shared product images have no `srcset`/`sizes`, and the hosted renderer explicitly removes authored `srcset`. Image elements also omit intrinsic dimensions, although shared CSS reserves space for default cards and galleries. **Fix:** generate width variants and modern formats, preserve responsive selection, and carry dimensions through the catalog. [Upload storage](/Users/saramia/pagosYa/apps/api/src/uploads/uploads.service.ts:224), [formats](/Users/saramia/pagosYa/apps/api/src/uploads/uploads.service.ts:8), [stripping](/Users/saramia/pagosYa/packages/storefront-preview/src/source-preview.ts:64), [card sizing](/Users/saramia/pagosYa/packages/storefront-kit/kit/commerce.js:185).

5. **Publication API does not require browser-check evidence — M.**  
   Studio blocks its publish button until checks pass, but the API only verifies the snapshot and structural commerce contract before changing the published revision. The contract checks hooks, script references, and configured pages—not successful browser execution. **Fix:** require a server-generated check result tied to the exact snapshot/runtime digest. [Studio guard](/Users/saramia/pagosYa/apps/merchant-studio/src/source-studio.ts:569), [API guard](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-publishing.service.ts:84), [contract](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-commerce-contract.ts:6).

6. **Rollback cannot recover an earlier commerce runtime — M.**  
   Every public revision is passed through `currentSourceRuntime`, which replaces its commerce code with the current kit. Republishing an older design therefore retains any current runtime regression. **Fix:** version the trusted runtime separately, record its digest with publication, and support controlled runtime rollback. [Public substitution](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-publishing.service.ts:146), [replacement](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-runtime.ts:13).

7. **Generated React homepage copy is absent from the server SEO extraction — M.**  
   Compiled HTML contains an empty title and empty React root. SEO extracts headings/descriptions from that HTML, not the separately stored React layout, so generated homepage copy falls back to store-level metadata instead of entering the initial SEO document. **Fix:** persist explicit page metadata and safe content blocks, or prerender them into the published artifact. [Compiled shell](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-next.ts:363), [SEO extraction](/Users/saramia/pagosYa/apps/api/src/store-seo/store-seo.service.ts:17), [fallbacks](/Users/saramia/pagosYa/apps/api/src/store-seo/store-seo.service.ts:42).

8. **Palette contrast correction covers only part of the interface — M.**  
   Correction excludes custom cards, samples the card heading, and skips correction at ratios ≥3:1. It does not enforce contrast across descriptions, buttons, forms, or generated sections. Normal text generally requires 4.5:1 under WCAG AA. **Fix:** validate token pairs and rendered text/control states, including custom cards and both themes. [Correction scope](/Users/saramia/pagosYa/packages/storefront-kit/kit/commerce.js:1260), [threshold](/Users/saramia/pagosYa/packages/storefront-kit/kit/commerce.js:1275), [WCAG criterion](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum).

9. **Shared storefronts lack a merchant-policy baseline — M.**  
   Product information provides details and delivery-location tabs, but no returns-policy field or delivery-time detail. Shared footers omit privacy/terms links; `privacy.js` supplies tracking preferences rather than merchant policy pages. **Fix:** add merchant-authored privacy, terms, returns, and delivery information, with persistent footer and purchase-area links. [Product information](/Users/saramia/pagosYa/packages/storefront-kit/kit/commerce.js:893), [footer](/Users/saramia/pagosYa/packages/storefront-kit/kit/product.html:3), [privacy panel](/Users/saramia/pagosYa/packages/storefront-kit/kit/privacy.js:28).

10. **Every store receives a broad shared runtime plus separate React page bundles — M.**  
    Measured locally: commerce/privacy/retention total **224.0 kB raw**, approximately **56.6 kB gzip** in an in-memory compression check—not an observed transfer size. The compiler independently bundles React/ReactDOM for each page, and the snapshot carries those bundles. **Fix:** extract shared framework chunks and load optional reviews, retention, and checkout features when needed. [Runtime composition](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-runtime.ts:14), [page bundling](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-next.ts:337).

11. **Fonts are copied whole and preload hints are discarded — M.**  
    Only referenced kit fonts are included, which is good, but the implementation copies complete TTF files without subsetting/conversion. Bundled files range from **62,284 to 408,496 bytes**. `font-display:swap` is requested in generation instructions; the bundler does not enforce it. Hosted rendering removes preload links. **Fix:** ship Spanish-capable WOFF2 subsets, enforce loading declarations, and preserve validated font preloads. [Font bundler](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-fonts.ts:6), [preload removal](/Users/saramia/pagosYa/packages/storefront-preview/src/source-preview.ts:38).

12. **Generated external contact/navigation links can become inert — M.**  
    Static HTML anchors lose `href` unless they target an included HTML page or fragment. Links created later by React pass through a parent allowlist limited to specific commerce/article destinations, configured WhatsApp, and external checkout. Ordinary social, `tel:`, `mailto:`, or external policy links are not supported by this path. **Fix:** provide validated link categories and preserve approved destinations through the bridge. [Anchor rewriting](/Users/saramia/pagosYa/packages/storefront-preview/src/source-preview.ts:74), [parent allowlist](/Users/saramia/pagosYa/apps/checkout/src/source-storefront.ts:93).

13. **Collection navigation drops collection-specific parent SEO — M.**  
    Client navigation changes the URL to `/c/<slug>`, but calls `refreshStoreSeo` without the collection slug. Its API request consequently resolves to generic catalog metadata/canonical. The sitemap also enumerates products and ordinary pages without collection URLs. **Fix:** propagate collection identity through metadata refresh and include published collections in sitemap entries. [Navigation](/Users/saramia/pagosYa/apps/checkout/src/source-storefront.ts:67), [refresh request](/Users/saramia/pagosYa/apps/checkout/src/store-seo.ts:9), [sitemap entries](/Users/saramia/pagosYa/apps/api/src/store-seo/store-seo.service.ts:59).

14. **Existing checks cannot establish keyboard/focus accessibility — M.**  
    Studio’s shopping probe replaces `HTMLElement.prototype.focus` with a no-op. Source preflight checks missing alt attributes in HTML, while React generation is checked before compiled HTML is added. These checks therefore leave focus behavior and JSX image-alt coverage unverified. **Fix:** add isolated keyboard navigation/focus assertions and inspect rendered accessibility semantics. [Disabled focus](/Users/saramia/pagosYa/apps/merchant-studio/src/source-shopping-probe.ts:4), [HTML-only alt check](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-preflight.ts:83), [generation ordering](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-generation.service.ts:535).

15. **Standalone Next exports omit shared catalog/collection pages — M.**  
    Hosted runtime adds `productos.html` and `coleccion.html`, but Next export emits its three React pages and filters public files without carrying those HTML pages. Its bundled server also resolves literal files rather than hosted pretty routes. **Fix:** export equivalent catalog/collection routes and verify all exported navigation and sitemap destinations. [Hosted additions](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-runtime.ts:25), [export filtering](/Users/saramia/pagosYa/apps/api/src/storefront-source/source-next.ts:400), [standalone routing](/Users/saramia/pagosYa/packages/storefront-kit/kit/server.mjs:12).
