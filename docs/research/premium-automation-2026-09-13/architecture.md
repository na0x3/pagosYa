# Durable design improvement workflow

Implement an additive opt-in production workflow over the existing generator. Merchant starts one job on an exact source revision with idempotent request ID, page/product identity, model and total credit cap. No automatic publishing. Studio gets start/status/cancel/resume controls separate from removed legacy visual-review tools.

PostgreSQL job row: store/merchant authorization through store relation; activeStoreId unique across jobs; revision/digest; state/stage; generation counter lease token; heartbeat; cancellation flag; max/reserved/settled budget; bounded repair attempts; JSON checkpoints and per-stage receipts. A scheduled worker claims using compare-and-swap, heartbeats while running, and fences every write. It runs one stage per claim. Capture is nonpaid and safely repeatable. Paid stage reserves its full allowance in PostgreSQL before any API call. Unknown usage keeps the reservation. A crashed paid stage becomes interrupted, never silently replays; explicit resume can spend another bounded allowance. Completed stages are reused. Cancellation aborts provider calls and prevents subsequent stages. Published revision remains unchanged.

Stages: capture baseline; review baseline; repair private candidate if major findings; capture candidate; compare baseline/candidate; accept or retain baseline. At most two repair candidates, each based on the original revision to avoid compounding regressions. Reports and images identify source digest, runtime digest, catalog digest, viewport and product. Capture readiness/overflow and authoritative commerce contract are hard gates, separate from model preference. Model comparison can choose baseline/candidate/uncertain. An uncertain or regressed candidate never replaces the baseline. Final apply is transactional with source revision CAS and job lease/cancellation check; racing merchant edits make the job stale. Keep candidate/checkpoints on failure for diagnosis.

Existing generator gains a narrow internal candidate mode: validate and build using existing code, prohibit product/catalog changes, return prepared snapshot instead of appending revision, and accept AbortSignal. Existing direct generation behavior stays unchanged. SourceProjectsService exposes normalization and an optional transaction fence used only by this workflow. Existing source generation's per-store active slot still serializes provider work against chat generation.

Budget is conservative estimated provider spend, not invoice certainty. Reserve caps across stages and settle only from complete known usage. No claiming exactly-once remote inference when a process can die after dispatch. Receipts distinguish observed spend from reservation held for unknown calls. Review/repair are opt-in behind an environment flag during initial rollout, with a global kill switch. Default legacy chat path remains usable.

Validation: authorization/idempotency, concurrent claims, expired lease fencing, paid interruption and safe resume, cancellation during generation, persistent shared budget and unknown usage, stale source and catalog, candidate rejection, atomic commit/cancel race, no automatic publication, UI reload/resume behavior, and actual local worker execution. Broader experiment: six held-out catalogs × three repetitions × baseline/candidate workflow = 36 generated outputs, stable fixture assets and budgets, preserve failures and judge pairwise with order masking. Include controlled edit preservation checks. This is evidence, not a calibrated universal beauty score.

## Implemented refinements after Claude review

- Capture hydration is temporary; canonical baseline/candidate bytes are persisted independently from visual assets.
- The unpaid baseline stage checks shopping eligibility. Unsupported/all-unavailable samples stop before paid review; mixed samples can proceed when at least one purchase is verifiable. Actual candidate failures or no passing sample prevent apply.
- `repairs` counts prepared candidates. Interrupted attempts keep their candidate index and held receipt; subsequent dispatch must fit the remaining allowance and per-stage attempt bound.
- `availableAt` delays chat-slot waits and transient conflicts, preventing oldest-job starvation. Serializable apply pauses its heartbeat and can retry a serialization conflict with the same artifact.
- Retention revision joins the catalog fingerprint; store updates cover locations. Pending receipts become unknown on cancellation. The UI rejects out-of-order poll responses and preserves historical views.
- An authored fixed drawer must not override embedded checkout flow; the shared runtime explicitly protects this layout invariant.

General rollout is opt-in. The provider balance blocked completion of the live comparative acceptance gate; see results.md. Private artifacts expire after 30 days for terminal jobs, in bounded hourly batches. Failed/interrupted jobs become non-resumable EXPIRED when their evidence is removed; financial receipts and source revisions remain. The current local batch has bounded inputs and no ongoing paid processes.
